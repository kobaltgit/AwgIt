# Регламент разработки AwgIt (GEMINI.md)

Данный документ является обязательным сводом правил, ограничений и стандартов разработки для AI-агентов и разработчиков, работающих над проектом **AwgIt**.

---

## 1. Философия и Миссия Проекта

> **AwgIt** — ультралегковесная панель управления клиентами AmneziaWG (AWG) для маршрутизаторов OpenWrt. 
> Основная ценность: **0% фоновой нагрузки на процессор и оперативную память роутера** при эстетике и удобстве интерфейсов уровня `wg-easy`.

Любое архитектурное или техническое решение должно оцениваться через призму:  
*«Не создаст ли это фоновую нагрузку на слабом роутере со 128 МБ RAM?»*

---

## 2. Категорически ЗАПРЕЩЕНО (Forbidden / Red Lines)

1. **Никаких баз данных и фоновых демонов:**
   * ❌ **Запрещено** добавлять СУБД: SQLite, PostgreSQL, MySQL, Redis, LevelDB и т.д.
   * ❌ **Запрещено** запускать постоянные фоновые демоны, службы, cron-таймеры, сервисы мониторинга.
   * Бэкенд (`src/awg-api`) работает строго по схеме **CGI on-demand**: вызывается сервером `uhttpd` в момент HTTP-запроса и немедленно завершает работу после отправки ответа.
2. **Никаких тяжелых языковых рантаймов:**
   * ❌ **Запрещено** внедрять Node.js, Python, Ruby, PHP, Java, Perl на роутере.
   * На роутере разрешены только штатные системные утилиты OpenWrt: `/bin/sh` (BusyBox ash), `uci`, `awg` / `amneziawg`, `awk`, `sed`, `grep`.
3. **Никаких Node.js сборок и npm во фронтенде:**
   * ❌ **Запрещено** добавлять `package.json`, `node_modules`, Webpack, Vite, React, Vue, Tailwind CLI, Sass.
   * Фронтенд должен оставаться чистым **Single-File SPA** (Vanilla HTML5 / Modern CSS / Vanilla JS), готовым к открытию напрямую веб-сервером `uhttpd`.
4. **Никаких внешних CDN и сетевых зависимостей:**
   * ❌ **Запрещено** подключать внешние шрифты (Google Fonts), скрипты (cdnjs, unpkg) или CSS-библиотеки через сеть.
   * Все ассеты и библиотеки (например, `qrcode.min.js`) должны быть вшиты локально. Панель обязана полноценно работать в изолированной локальной сети без выхода в интернет.
5. **Запрещены Bash-специфичные конструкции (Bashisms):**
   * ❌ В скриптах роутера (`/bin/sh`) запрещены: `[[ ... ]]`, массивы `arr=(1 2 3)`, `${var//from/to}`, `<<<`, `read -a`, `declare`.
   * Стандарт — строгий **POSIX / BusyBox ash**.
6. **Запрещена деградация флеш-памяти (Flash Wear-Out):**
   * ❌ **Запрещено** непрерывно писать логи, временные файлы или дампы во флеш-память роутера (`/etc`, `/www`, `/overlay`).
   * Любые временные файлы разрешены только в RAM-диске: `/tmp/` (ramfs). Конфигурация пишется в `/etc/config/network` только по явному действию пользователя.

## 3. ОБЯЗАТЕЛЬНО к выполнению (Mandatory / Must-Do)

1. **Хранение данных строго через OpenWrt UCI:**
   * Все серверные метаданные (имя, группа, заметка, дата создания, пароль) хранятся исключительно в конфигурации `/etc/config/network` через штатную системную утилиту `uci`.
   * Пользовательские параметры отображения (свернутость групп, сортировка, светлая/темная тема) сохраняются в браузере через `localStorage`.
2. **Строгая санитизация и валидация входящих данных:**
   * **Публичные и приватные ключи:** строгая валидация формата WireGuard/AmneziaWG Base64 (ровно 44 символа, символы `A-Za-z0-9+/=`).
   * **Имена клиентов:** фильтрация через `sanitize_name` (только латиница, цифры, пробел, дефис, точка, подчеркивание, макс. 64 символа).
   * **IP-адреса:** строгая проверка IPv4 и CIDR в диапазоне `10.9.0.0/24`.
3. **Безопасность API (Auth Guard):**
   * Если администратором задан мастер-пароль, каждый вызов API обязан проверять заголовок `X-Awgit-Password`.
   * При несовпадении немедленно возвращать ответ `401/403` в JSON.
4. **Энергоэффективность и бережный поллинг:**
   * Использовать `Page Visibility API` во фронтенде: замедлять опрос роутера при неактивной вкладке и останавливать при фоновом режиме.
5. **Синхронизация инсталляторов:**
   * Любые изменения в составе файлов веб-интерфейса или API должны синхронно отражаться как в POSIX-инсталляторе `src/install.sh`, так и в PowerShell-скрипте `src/install.ps1`.
6. **Тестирование перед сдачей работы:**
   * Перед фиксацией изменений обязателен запуск тест-сьютов:
     ```bash
     sh tests/run_all_tests.sh
     ```
     (включает проверку POSIX-синтаксиса, CGI-моков, валидации входных данных и целостности фронтенда `tests/test_frontend_integrity.js`).
7. **Ведение документации:**
   * Любые архитектурные решения фиксируются в [docs/CHRONICLE.md](file:///d:/Projects/active/AwgIt/docs/CHRONICLE.md).
   * Статусы задач отмечаются в [docs/ROADMAP.md](file:///d:/Projects/active/AwgIt/docs/ROADMAP.md) и [docs/CHECKLIST_v0.2.0.md](file:///d:/Projects/active/AwgIt/docs/CHECKLIST_v0.2.0.md).
8. **Обязательная двуязычность (Mandatory Bilingual RU/EN):**
   * Все без исключения видимые строки интерфейса (`src/index.html`), включая заголовки, поля ввода, плейсхолдеры, тултипы, модальные окна, уведомления, фильтры, бейджи и содержимое автономного HTML-паспорта клиента **ОБЯЗАНЫ** иметь синхронные переводы на два языка: **Русский (RU)** и **Английский (EN)**.
   * Все сообщения и интерактивные диалоги инсталляторов (`src/install.sh`, `src/install.ps1`) обязаны выводиться через хелперы локализации `msg` / `Msg` на двух языках.
   * Категорически запрещено оставлять хардкод строк только на одном языке.

## 4. Как правильно делать (Best Practices & Architecture)

### 4.1. Бэкенд (`src/awg-api`)
* Возврат заголовков: всегда отдавать `Content-Type: application/json; charset=utf-8` и заголовки запрета кэширования (`Cache-Control: no-cache, no-store`).
* Ошибки: при любых сбоях отдавать валидный JSON `{"status":"error","message":"..."}` с кодом возврата `0` (чтобы `uhttpd` корректно доставил ответ фронтенду).
* Работа с ядром: для применения пиров на лету без даунтайма использовать `awg set awg0 peer ...` перед фиксацией в `uci commit network`.

### 4.2. Фронтенд (`src/index.html`)
* Стилизация: чистый CSS с CSS Variables (`--bg-body`, `--bg-card`, `--border`, `--text`, `--green`, `--red`, `--blue`).
* Поддержка тем: переключение Dark / Light через атрибут `[data-theme="light"]`.
* Локализация: поддержка двух языков (RU / EN) с переключением на лету. Все ключи словарей `i18n.en` и `i18n.ru` должны строго совпадать.
* Адаптивность: корректная работа на смартфонах от 360px без горизонтального скролла.

### 4.3. Автономный HTML-паспорт клиента
* Генерируется на лету в браузере админа через `Blob` и `URL.createObjectURL`.
* Изображение QR-кода вшивается в Base64 (`data:image/png;base64,...`), чтобы файл работал автономно без скрипта генератора.
* Скачивание файла `.conf` внутри паспорта реализуется через локальный JavaScript Blob без обращений к серверу.
* Сам паспорт создается на том языке, который в данный момент выбран у администратора (RU или EN).

## 5. Чек-лист проверки кода (Definition of Done)

Перед сдачей любого этапа агент обязан проверить:
- [ ] Полный набор тестов `sh tests/run_all_tests.sh` завершается без ошибок (`exit 0`), включая проверку целостности фронтенда, моки CGI и синтаксис `sh -n`.
- [ ] Все новые строки интерфейса и инсталляторов переведены на RU и EN (нет хардкода).
- [ ] Во фронтенде нет обращений к внешним ресурсам / CDN.
- [ ] Изменения не создают постоянных фоновых процессов на роутере.
- [ ] Отражены изменения в инсталляторах `install.sh` и `install.ps1`.
- [ ] Обновлены файлы документации (`CHRONICLE.md`, `CHECKLIST_v0.2.0.md`).
