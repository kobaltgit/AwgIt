# AwgIt: AmneziaWG Web Manager for OpenWrt (Архитектура и Описание Проекта)

> **AwgIt** — ультралегковесная панель управления клиентами AmneziaWG (AWG) с нулевыми накладными расходами, интегрированная напрямую в OpenWrt без Docker, тяжелых рантаймов и сторонних демонов.

---

## 1. Контекст и Проблематика

### 1.1. Предыстория
В условиях масштабных блокировок протокола WireGuard мобильными операторами РФ (через комплексы ТСПУ / DPI РКН) стандартные решения перестали функционировать на сотовой связи (LTE). Переход на AmneziaWG решает проблему распознавания сигнатуры за счет параметров обфускации (`Jc`, `Jmin`, `Jmax`, `S1`, `S2`, `H1-H4`).

### 1.2. Проблема существующих решений
1. **Тяжелые Docker-контейнеры (wg-easy):** Требуют выделенного сервера, расходуют оперативную память, создают двойную трансляцию сетевых адресов (NAT) и при наличии прозрачных прокси (sing-box / Passwall) на шлюзе могут приводить к зацикливанию маршрутов, подмене портов и потере связности.
2. **Штатный LuCI в OpenWrt:** Предоставляет только «сырой» конфигуратор интерфейсов. Нет генерации клиентских конфигураций в 1 клик, нет визуализации QR-кодов, нет мониторинга активных пиров в реальном времени.

### 1.3. Миссия AwgIt
Создать автономный, эстетичный веб-интерфейс в тёмной теме (по образцу wg-easy), работающий **непосредственно на роутере OpenWrt**:
- **0% постоянной нагрузки на CPU/RAM** (отсутствие фоновых демонов).
- Генерация пиров в **один клик** с автоматическим созданием `.conf` и SVG/Canvas **QR-кода**.
- Полная интеграция со штатной подсистемой OpenWrt **UCI** (`/etc/config/network`) и ядром `kmod-amneziawg`.
- Безопасная маршрутизация: изоляция трафика AWG от прокси-туннелей (sing-box) через `fwmark` и `policy routing`.

## 3. Модульная структура

### 3.1. Frontend (`/www/awg/index.html`)
* **Технологический стек:** HTML5, Modern CSS (Glassmorphism / Dark Theme в стиле wg-easy), чистый легковесный JavaScript (без внешних тяжелых фреймворков).
* **Компоненты интерфейса:**
  * Верхняя панель: статус интерфейса `awg0`, публичный IP роутера, порт прослушивания, кнопка `+ Новый клиент`. На мобильных устройствах длинные данные сокращаются во избежание горизонтального скролла.
  * Карточки клиентов: имя, виртуальный IP (`10.9.0.x`), объем принятого/переданного трафика, время последнего хэндшейка.
  * Живой индикатор «Мягкое дыхание»: аппаратный цикличный CSS glow-эффект (`status-breathe`) для активных сессий (0% нагрузки на CPU).
  * Бегущая мини-диаграмма (SVG Sparkline): сглаженный график сетевой активности скользящего окна в реальном времени с адаптивным градиентом.
  * Мобильная адаптивность (CSS Grid): 3-ярусная компоновка на экранах смартфонов (верх: аватар/имя/тумблер; центр: полноразмерный график; низ: счетчики скорости и кнопки действий).
  * Энергоэффективный поллинг (Visibility API): динамическое переключение частоты опроса (3 сек в фокусе / 15 сек при неактивной вкладке).
  * Модальное окно QR-кода: мгновенная отрисовка QR с параметрами обфускации, кнопка скачивания `.conf`, кнопка копирования в буфер обмена.
  * Управление клиентом: тумблер включения/выключения пира, быстрое скачивание `.conf` в 1 клик, редактирование, удаление.

### 3.2. Backend API (`/www/cgi-bin/awg-api`)
* **Технологический стек:** Shell-скрипт стандарта POSIX (`/bin/sh`) под uhttpd.
* **Эндпоинты:**
  * `GET /cgi-bin/awg-api?action=status` — опрос состояния `awg show awg0`, получение списка пиров, объемов трафика и таймстампов.
  * `POST /cgi-bin/awg-api?action=create` — создание нового клиента:
    1. Автоматический расчет следующего свободного IP в пуле `10.9.0.0/24`.
    2. Генерация пары ключей: `/usr/bin/awg genkey` и `/usr/bin/awg pubkey`.
    3. Добавление записи `amneziawg_awg0` в `/etc/config/network`.
    4. Применение пира на лету через `awg set awg0 peer <pubkey> allowed-ips <ip>/32`.
    5. Формирование готового конфига со всеми параметрами сервера (`Jc`, `Jmin`, `Jmax`, `S1`, `S2`, `H1-H4`, безопасный DNS, Endpoint).
  * `POST /cgi-bin/awg-api?action=toggle` — включение/выключение пира через `uci set network.@amneziawg_awg0[X].disabled` и `awg set`.
  * `POST /cgi-bin/awg-api?action=delete` — удаление пира из конфигурации.

## 4. Сетевая Безопасность и Маршрутизация

1. **Изоляция от сторонних прокси (sing-box / VLESS):**
   * Интерфейс `awg0` помечает исходящие транспортные UDP-пакеты меткой `fwmark 0x1000`.
   * Системное правило `ip rule add fwmark 0x1000 lookup main priority 8999` отправляет ответы роутера напрямую через физический WAN (`eth0` -> GPON-модем), минуя виртуальный туннель `tun0` (таблицу 2022).
   * Исключается подмена обратного порта со стороны conntrack/NAT.
2. **Защита от утечек DNS (Anti-DNS-Leak):**
   * В клиентских конфигах в качестве основного DNS жестко назначается шлюз интерфейса `10.9.0.1` (локальный dnsmasq роутера), что сохраняет защиту от пробивов для рабочих нейросетей, и внешний надежный DNS (`77.88.8.8`) в качестве отказоустойчивого резерва.
   * Исключается сотовый IPv6-блэкхол за счет явного указания `AllowedIPs = 0.0.0.0/0` (без сотового `::/0`).

## 5. Системные требования
- **ОС маршрутизатора:** OpenWrt 23.05+ (x86_64 или ARM).
- **Установленные пакеты:** `kmod-amneziawg`, `amneziawg-tools`.
- **Веб-сервер:** `uhttpd` (входит в стандартную поставку OpenWrt).
- **Доступ:** Локальная сеть роутера (`http://<router_ip>/awg`, по умолчанию `192.168.1.1/awg`).
